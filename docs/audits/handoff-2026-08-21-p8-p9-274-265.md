## 2. **Read this before you trust a full-suite run**

**A green-looking full run this session was not green, and I reported it as green.** The #274 run
printed:

```
Test Files  1 failed | 393 passed | 3 skipped (398)
#184 AC-4: recovered — all 398 files accounted for after 2 attempts (1 crash-triggered retry).
```

Two traps, both now recorded in INDEX's corrected #274 row:

1. **`#184 AC-4: recovered — all N files accounted for` means every file *ran*. It does not mean they
   passed.** It prints immediately after the summary line that says otherwise, and reads like an
   all-clear.
2. **Check the suite's exit code, not a trailing `echo`'s.** `node scripts/run-tests.mjs > log; echo
   "exit=$?"` sends the echo to the *task* stream while the log holds only vitest's output — so
   `[exited with code 0]` was the echo succeeding. `run-tests.mjs` exits 1 correctly
   (`process.exit(aggFiles.failed > 0 || aggTests.failed > 0 ? 1 : lastExitCode)`); read **its** code.

**The failure itself:** `schedules-route-conflicts.e2e-spec.ts` hand-builds its test module, so #274's
new `CandidateQueryService` controller dependency made `beforeAll` throw → vitest reports the file's
tests as **skipped** while the file counts as **failed**. That file's own comment, written during
#273, predicts this exactly. **Any issue that adds a constructor dependency to `SchedulesController`
must add it there too.**

**Background long-runs are being terminated by this environment.** Two full-suite runs were killed
mid-flight (at 114 and 37 files, both green, no failure). The foreground cap is 10 min and the suite
takes ~11.5. **What works:** `run-tests.mjs` accepts an explicit file list, so split and run in the
foreground:

```bash
find test -name "*.spec.ts" -o -name "*.e2e-spec.ts" | tr -d '\r' | sort > all-specs.txt
split -n l/4 -d all-specs.txt chunk
node scripts/run-tests.mjs $(cat chunk00 | tr '\n' ' ')   # ~2-4 min each
```

**Measured clean, 2026-08-21, after the fix: 400 files / 397 passed / 3 skipped / 0 failed;
1969 tests passed / 5 skipped; exit 0 on all four chunks.** One #184 crash inside chunk 2,
auto-retried and recovered. The 3 skipped files / 5 skipped tests are pre-existing.

## 4. Facts that will cost you time to rediscover

**New this session, and all measured rather than assumed:**

- **`meta.target` does not exist on a P2002 in this repo.** The field every Prisma example keys on is
  absent under this driver adapter. The constraint identity is at
  `meta.driverAdapterError.cause.constraint.fields`; the index name is only in `originalMessage`.
  `src/common/unique-violation.ts` discriminates on `meta.modelName` — **exact only because
  `batch_assignment_tickets` and `work_schedules` each carry exactly one unique.** #259 adds
  `ux_dispatch_run_zones_one_running_per_zone`; if you ever need to tell two constraints apart on one
  model, that helper must start reading `constraint.fields`.
- **A P2002 aborts its interactive transaction.** Postgres answers everything after it with *"current
  transaction is aborted, commands ignored until end of transaction block"*. So catch-and-continue
  inside a `$transaction` is impossible — recovery must let it roll back and retry the whole thing.
  **#259's admission is an insert-and-catch, so this applies directly to it.**
- **That rollback is load-bearing for audit honesty.** `AuditService.withAudit` writes the audit row
  *inside* the caller's transaction, so throwing out of the work callback is how you get "no audit row
  claiming an action that did not happen" for free. `src/common/lost-race.ts` (`LostRaceError`,
  `stampOnceOrLose`) is the reusable form.
- **`work_schedules_one_active_per_se_zone_day` keys `(se_id, zone_id, date_from)` — not `date_to`.**
  `ensureSchedule` used to match `date_to` too, which 500'd **every** manual assign to an engineer who
  had any live schedule with a differing or null `date_to`. Fixed. `batch-assignment.service.ts:128`
  had always matched the constraint; the two now agree.
- **`OVERRIDDEN` is a LIVE schedule status** (`LIVE_SCHEDULE_STATUSES`, #153) while `COMPLETED` /
  `PARTIAL` are terminal — so writing it by primary key **resurrects a closed day plan**.
  `flagOverridden` and `swapSe` both did. Guarded now. Any new writer of `work_schedules.status`
  should carry `liveScheduleFilter()` in its `where`.
- **A `beforeAll` that throws reports as `skipped` tests + a `failed` file.** Third sighting (#273,
  #265, and #274's regression). Read the *file* counts, not the test counts.
- **Windows/tooling:** large `python - <<'PY'` heredocs intermittently fail to parse in the Bash tool
  (`unexpected EOF while looking for matching`); write the script to a file, or use the Write tool.
  `sed -i` and small heredocs are reliable. There is **no prettier and no backend eslint** in this
  repo — formatting is by hand, so match the file you are in.
- **When a python patch script asserts, nothing was written** if the `write` is the last statement —
  a failed `assert s.count(old)==1` saved a bad edit twice this session. Keep that shape.

**Still true from the predecessor handoffs** (not repeated): plants have no `company_id` ·
