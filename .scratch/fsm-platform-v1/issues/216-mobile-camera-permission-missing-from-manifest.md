# 216 — `android.permission.CAMERA` is missing from the generated manifest; both photo flows dead on device

Status: ready-for-agent
Type: AFK · Mobile · Build/config
Parent: [#197](./197-mobile-pilot-readiness-remediation-epic.md) · Filed 2026-08-05
Blocked by: nothing (independent of [#209](./209-mobile-build-pipeline-device-install.md), which
found it but deliberately did not fix it)

## Root cause

`app.json` does not list `expo-image-picker` in its `plugins` array, so the library's config plugin
never runs during `expo prebuild`. That plugin is what injects `<uses-permission
android:name="android.permission.CAMERA"/>`. Without it the permission is simply absent from the
generated `AndroidManifest.xml`, and **Android refuses to grant a runtime permission the manifest
never declared** — `requestCameraPermissionsAsync()` resolves `granted: false` immediately, with no
system dialog shown to the user.

This was invisible until [#209](./209-mobile-build-pipeline-device-install.md) produced the first
native build. Nothing in Jest or `tsc` can see it: every test mocks `expo-image-picker`.

## Evidence — verified 2026-08-05

- `apps/mobile/android/app/src/main/AndroidManifest.xml` (generated by prebuild) declares
  `ACCESS_COARSE_LOCATION`, `ACCESS_FINE_LOCATION`, `INTERNET`, `READ_EXTERNAL_STORAGE`,
  `RECORD_AUDIO`, `SYSTEM_ALERT_WINDOW`, `VIBRATE`, `WRITE_EXTERNAL_STORAGE` — **and no `CAMERA`**.
- `apps/mobile/app.json` `plugins`: `expo-router`, `expo-splash-screen`. No `expo-image-picker`.
- Both call sites guard on the permission and bail:
  - `src/vouchers/VoucherFormScreen.tsx:48-52` — `requestCameraPermissionsAsync()` → on `!granted`,
    `setError('CAMERA_PERMISSION_DENIED')` and return.
  - `src/tickets/install/InstallFormScreen.tsx:38-42` — identical shape.
- So the failure is not a crash. The SE taps the capture control and gets a
  `CAMERA_PERMISSION_DENIED` error with **no way to recover from inside the app** — there is no
  system prompt to accept, and no Settings deep-link.

## Why this matters more than it looks

It directly contradicts the mobile device-readiness audit
(`audit/mobile-device-readiness-2026-08-04.md`), which is the document the pilot plan leans on:

- §"Still absent", line 64: *"Voucher and Install photos work; Troubleshoot's 4 named slots don't
  exist on the screen."*
- §PART 3, item 6, line 159: *"**Vouchers** — empty list. **The one screen you can exercise for
  real today**: New Voucher → camera capture → real upload (`media_objects` exists in dev DB) →
  submit creates a real row."*

Both claims are false on a real handset. The audit was written against source and a running
backend, before any APK existed — a reasonable read of the code, but the manifest is generated, not
authored, so it could not have been checked. **The one screen the audit said was exercisable is not
exercisable**, and it fails at the first tap. Correcting that expectation matters as much as the
one-line fix, because the pilot readiness picture currently rests on it.

## Scope

**In:** add `expo-image-picker` to `app.json` `plugins` with its permission copy; re-run prebuild;
confirm `CAMERA` appears in the generated manifest; verify both flows end-to-end on a handset;
correct the two audit claims above.

**Out:** the Troubleshoot form's unwired photo slots (separate, already noted as having no
follow-up issue — file one if still missing). Any change to the upload API or `POST /media/upload`.
Media display in admin ([#203](./203-admin-media-display.md)).

## Acceptance criteria

- [ ] `expo-image-picker` is listed in `app.json` `plugins`, with `cameraPermission` copy that says
      why the app wants the camera (it is shown in the system dialog)
- [ ] After `npx expo prebuild --platform android`, the generated
      `android/app/src/main/AndroidManifest.xml` contains
      `<uses-permission android:name="android.permission.CAMERA"/>`
- [ ] The `android/` diff is reviewed and committed (that directory is tracked — see
      [#209](./209-mobile-build-pipeline-device-install.md) and
      `docs/runbooks/mobile-android-build.md`; do **not** run `prebuild --clean`)
- [ ] On a physical handset: Voucher → New Voucher → capture shows the **system permission dialog**,
      and on accept the camera opens, the photo uploads, and the voucher row is created
- [ ] On a physical handset: the Install form capture path does the same
- [ ] A denied permission still leaves the SE a route forward — at minimum the error copy tells them
      to enable Camera in system settings, rather than a bare `CAMERA_PERMISSION_DENIED` code
- [ ] `audit/mobile-device-readiness-2026-08-04.md` lines 64 and 159 are corrected in place with a
      dated note, so the pilot plan stops resting on a claim that was never true on device

## Verification

```bash
cd apps/mobile
npx expo prebuild --platform android          # NOT --clean
grep CAMERA android/app/src/main/AndroidManifest.xml   # must match
npx expo run:android                          # handset on USB
# then on the handset: Vouchers → New Voucher → capture → expect a SYSTEM DIALOG, not an error
```

## Risk if deferred

Photo capture is not a nice-to-have here: the Voucher receipt and the Install photo are both
evidence artefacts the back office relies on. Shipping a pilot build where the capture control
fails on first tap, with no in-app recovery, wastes the pilot — and because the readiness audit
records these flows as working, nobody would think to check them first.

## Size estimate

S — the fix is one `app.json` entry plus a prebuild. The cost is the handset verification and the
audit correction, neither of which is optional.
