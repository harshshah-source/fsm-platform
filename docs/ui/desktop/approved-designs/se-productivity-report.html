Why this shape

A zone has a roster, and the question a manager brings to this page is which of my engineers needs attention — not "tell me about Ramesh". A table answers that in one read and a per-SE scorecard cannot: it makes you already know the name before you can look it up. The per-SE view is a reasonable second screen later, reached by clicking a row; it is the wrong first one.

It reuses what #364 built rather than inventing a parallel mechanism: the filter bar lives inside the same header band as the freshness stamp and the scope chip, because that band is what states the scope of the numbers under it. The scope chip renders the server's echoed zone, never the local pick — a ZM whose zone is clamped must see the zone they are actually reading.

Small samples must not be dressed as rates. A floating SE with six closures has no meaningful first-time-fix percentage, and rendering one invites a manager to act on noise. Below the threshold the rate columns show —, and the footer says why. The count columns are always shown, because a count of six is a true fact about six jobs.

This is a diagnostic surface, not a league table. The design deliberately does not rank, badge a "best" engineer, or colour a whole row. Only individual out-of-band metrics are marked, in the same amber/crimson grammar the other two approved designs use, so the eye lands on a number worth asking about rather than on a person worth blaming. Ordering is by name by default — sortable, but never pre-sorted worst-first.

What the page must not do

  • Never show se_repaired_closures unsplit. Audit finding F7: that column mis-attributes departure closures, so an engineer whose plants had vehicles leave the fleet reads as more productive than one who repaired devices. #365 fixes the aggregation (fleet-uptime-aggregation.service.ts) before the page exists — a page built on the unsplit column would publish the mis-attribution to the people who make staffing decisions. Repair and Departure are separate columns here for that reason, and the split is the prerequisite, not a nicety.
  • No live recomputation. Every figure comes from the daily summary tables, and the stamp says which rebuild. A page that recomputed on request would disagree with the ZM scorecard beside it.
  • Zone clamp is server-side. A ZM sees their own zone; CSM and OH see all. The dropdown is a convenience, never the enforcement.

Grammar

Shared with assign-work-console.html and todays-dispatch-crew-deck.html so the boards read as one product: amber = worth a look, heavy crimson = act now, dashed border = a value whose freshness is provisional. Nothing here relies on colour alone — every flagged number is also the outlier in its column, and the design survives grayscale.
