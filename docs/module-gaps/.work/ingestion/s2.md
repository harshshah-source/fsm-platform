## Verdict against the yardstick

Yardstick asks one thing: when a run fails or hangs, does a human find out?
**Answer: yes for a run that FAILS, no for a pipeline that STOPS.**

The failure path is genuinely well built — better than the rest of this survey's modules.
Heartbeat-based reaper (`stale-run.ts:36`, 30 min, not `started_at`), first-writer-wins `finishRun`
(`snapshot-run.service.ts:108`), a streak derivation shared by both surfaces so banner and card cannot
disagree (`ingestion-alert.ts:138` → `snapshot-query.service.ts:110` + `health.service.ts:394`), and a
banner on every page (`AppRoutes.tsx:62`) that refuses to promote a PARTIAL watermark to freshness
(`snapshot-query.service.ts:116`). C1 and C2 are PARTIAL, not absent, and the remaining work is small.

The hole is the silence case. Every detector counts **runs that happened**: streak walks finalized
rows (`ingestion-alert.ts:146`), the reaper fires only inside `startRun()` (`snapshot-run.service.ts:63`),
and the banner alerts on FAILED / stuck-RUNNING / wedged only (`SnapshotBanner.tsx:86`). Zero runs is
streak 0, no RUNNING row, and a calm grey "data as of …" line rendering a week-old timestamp
(`SnapshotBanner.tsx:126-141`). Nothing in this repo thresholds an absolute age — `ageMinutes` is
computed at `health.service.ts:409` and then never rendered. → **ING-03**.

## The payload-shrink finding (ING-02)

Worth naming on its own because it is one edit and it unlocks three capabilities.
`health.service.ts:203-213` returns **seven** sections. `apps/admin/src/api/integrationHealth.ts:48-55`
declares **five fields** and drops four of them: `source` (VPN/config down — invisible),
`masterSync/snapshot` freshness age, `reconciliation` (source-vs-FSM row drift, `:283`), and
`lifecycle` (`:342` — the drift + `quietRunsAlert` check built specifically because
`entity_stats.departures` recorded 33 quiet runs while nothing read it). The backend already computes
the answer to "is ingestion lying to me"; the client throws it away before render.

## Flags — looking at absence, not at OFF

Module reads four env vars. Three are tuning (`AUTOPLANT_SNAPSHOT_CHUNK_SIZE`,
`AUTOPLANT_SOURCE_UTC_OFFSET_MIN`, `PARTITION_MAINTENANCE_CRON`). One is a real feature flag:
`PARTITION_MAINTENANCE_ENABLED`, **default OFF by design** (`partition-maintenance.service.ts:63`).
ING-07 is therefore filed as flag-off, not absent, and at S1 — the finding is only that no surface
tells an operator the sweep is dormant. Everything else above is genuine absence.
