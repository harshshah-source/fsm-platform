Why a stop and not a banner

An engineer's day is one ordered sequence, and the pickup is genuinely the first thing in it — they cannot do the job at stop 1 without the part. Rendering it as a stop keeps the ordering literal: stop 0 comes before stop 1, and nobody has to infer where in the day the warehouse visit belongs. A banner above the list says "also, collect something", which is exactly the ambiguity the stop numbering exists to remove, and it detaches the pickup from the sequence it is part of.

It is a different kind of stop, not a different-looking plant. The violet left rule and the Pickup tag say "this is not a plant visit" — no ticket list, no device count, no SLA, because none of those exist for a warehouse. The row shows the one thing the dispatcher needs: which parts, and how many. Listing them beats a bare label; a dispatcher checking a plan should not have to open the component requests to learn what the engineer is carrying.

Colour is a kind, not a severity. Violet is used because the existing grammar already spends crimson on critical and amber on over-capacity; a pickup is neither urgent nor wrong, it is simply a different sort of thing. The tag carries the meaning on its own, so the row survives grayscale and colour-blind rendering.

Stop 0 appears only when it is real. One pickup stop when the plan has at least one ticket whose component request is SHIPPED and not yet RECEIVED; none otherwise. Never an empty pickup stop, and never more than one — an engineer makes a single warehouse visit, however many parts are waiting there.

What this pins for the implementation

  • DayPlanStop gains kind: 'PLANT' | 'WAREHOUSE_PICKUP' in packages/shared. A discriminated kind, not a boolean flag — the shapes differ (a pickup has parts and no tickets), and a boolean invites a renderer to read plant fields off a row that has none.
  • The pickup carries the request references and part names, since the row displays them. That is the contract the admin schedule detail renders and the mobile screen will later render too.
  • Sequence 0, so existing stop numbering is untouched and a plan without a pickup is byte-identical to today.
  • Mobile rendering is explicitly not in #366. When it is built it inherits this grammar — a distinct kind, first in the list, parts named — rather than inventing its own.
