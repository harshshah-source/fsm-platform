## C6 SE assignment threshold — clean, including the snapshot

`setting-authority.ts:18` is the single greppable authority table (OH + CSM only);
`canWriteSetting:57` gives the OH-never-locked-out rule; revert is OH-only (`:181`);
every write appends a `setting_changes` row inside the audited tx (`:219`).
**Snapshot question settled from source:** `dispatch-run.service.ts:1331` names
`SE_ASSIGNMENT_THRESHOLD_KEY` explicitly in `captureConfigSnapshot`, and `settings.service.ts:41`
seeds it in `SETTINGS_DEFAULTS` on every boot (`onModuleInit` → `seedDefaults:149`, upsert-if-absent).
So the row always exists: the snapshot's `settings` map records the **effective** value, and there is
no code-default-vs-DB-override ambiguity for this key. Not an O3. What static code cannot settle is
whether the engine *reads* it fresh per run — H-AC-4.

## C7 plant deactivation — E-26 confirmed, and worse on reactivate

`plant-deactivation.service.ts:229` ends the SE's day-plan rows
(`batchAssignmentTicket.updateMany → removedAt`) inside the deactivate transaction. The carrier for
telling a phone **already exists** — `DayPlanNotificationOutbox` (`schema.prisma:2899`), written by
`scheduling/day-plan-notification-outbox.ts` — and `plant-deactivation/` never touches it. So this is
a missing enqueue against a live carrier, not a new channel: **AC-02, C2 · S4 · DANGEROUS**.
`reactivate():97` closes the loop badly — it flips `reactivatedAt` and returns
`cancelledTicketsAtDeactivation: null` (`:116`); no ticket, cycle or plan stop comes back
(**AC-03**). An OH who deactivates the wrong plant cannot undo it from the console.

## C8 user accounts — the module's other S4

the repo is `auth/credential-seed.ts:21`, reached solely from `auth-fixture-seed.ts:141` and
`dev-seed.ts`. Login joins `credential` (`prisma-user-store.ts:32`). An account created from

`PATCH /org/users/:userId` exists (`users.controller.ts:29`) but `api/org.ts:105-112` ships only

cannot be disabled from the console (**AC-06, C4 · S3**), and role/zone are immutable after creation
(**AC-07, C5 · S2**).
