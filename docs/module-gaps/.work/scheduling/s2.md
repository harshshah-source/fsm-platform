## The one structural finding

The module's *producing* half is strong: outbox rows are written in the same tx as the dispatch
(`day-plan-notification-outbox.ts:22,44`), the drain claims-before-delivering
(`day-plan-notification-outbox.ts:99-117`). The *delivering* half is a stub returning `UNAVAILABLE`
for every external channel, and the mobile client has **no polling of any kind** — grep for
`setInterval|refetchInterval|useFocusEffect` in `HomeScreen.tsx` returns nothing. The app's own
workaround admits it: `dayPlanCues.ts:12-19` diffs day plans client-side "since the server has no
added/removed since signal", in memory, resetting on cold start.

So three S1 capabilities (C8 push, and the SE-facing halves of C7 and C9) and two spine edges
(E-05 BROKEN, E-24 PARTIAL) all bottom out on **one** missing adapter. SCH-05 folds into SCH-01.
SCH-02 (plant deactivation, E-26) is a *separate* nail in the same board: it strips stops from a live
plan and queues no outbox row at all, so even a working carrier would not save it.
