hand-off UI worth the name, and two live non-transactional orphans on the paths that matter.

## The two backlog leads — BOTH CONFIRMED LIVE
**Two-phase orphan on approve — CZ-01.** `cross-zone-escalation.service.ts:162-178`.
`override.assignTicket` commits, then a separate `crossZoneEscalation.update` sets APPROVED.
No shared transaction. Crash between → escalation PENDING on an assigned ticket. Retry hits
:163 `ALREADY_ASSIGNED` and returns with no reconciliation. Sharpest detail: `assignTicket`
already exposes an `inTransaction` callback built for exactly this (`override.service.ts:659`,
#325 RC-9) and approve does not pass it. Cheap fix, high severity.

**Sweep notification orphan — CZ-02.** `:99-115` are create + audit + notify, three
non-transactional writes in the per-ticket loop with **no try/catch** — a throw also kills the
sweep for every later ticket. Idempotency predicate `:83` is `crossZoneEscalations: { none: {} }`
— ANY row ever, any status — so the half-written ticket is excluded from every future sweep.
`flag()` :127-130 uses the correct status-scoped predicate for the same question. The two paths
disagree; that inconsistency is also H-CZ-3 (a once-denied Platinum can never auto-escalate again).

## C3 — deny/defer reverse path: EXISTS, thin
`decide()` :254-280 writes status + reason, audits, notifies the home ZM. Ticket never moves by
design (:62 — parallel decision record). So it is not a blank reverse path and **not** an S3
spine floor. Two soft edges: `notifyHomeZm` :319-320 returns silently when the zone has no ZM —
exactly the absent-ZM case the CSM cascade exists for (CZ-09); and `reviewDate` :271 is written
and never read as a trigger by anything (CZ-07), so defer-to-Friday and defer-to-December look
identical in the queue.

## C7 — does an approved escalation land in the target SE's worklist?

genuinely crosses the boundary and `drainRows` (:655) pushes post-commit through the real

target zone — not its ZM — is told, and the SE gets a generic "Day Plan updated". Per the
standing rule (a receiver that must notice the item is manual), that is H-CZ-1, an S3-shaped
claim a downstream walk must settle. SE mobile is auth-shell only, so no screen exists to check.
